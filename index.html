Part 1 · Build it

Gather your parts

On the Elegoo board, pins may be labeled with a D: D25 means pin 25.

Part 1 · Safety

One rail is the battery. Treat it that way.

Today the breadboard's top red (+) rail carries battery power, about 6 V. That's almost twice what the ESP32's pins can take.

1
Label it. Put tape on the top red rail and write "BATTERY 6V".
2
No ESP32 wire ever goes into the battery rail. The ESP32 connects only to the blue GND rail, the VCC pin, and the signal pins.
3
Battery switch OFF and USB unplugged while you wire.
4
Use the ESP32's 3V3 pin for VCC, not VIN or 5V.
If you smell something hot or a part gets hot to the touch: battery off, USB out, and call your teacher.
Step 1 of 6 · Mount the driver

TB6612 across the center gap

1
Push the TB6612 into the breadboard so it straddles the center gap, one row of pins on each side, like a bridge.
2
Turn it so the VM, VCC, GND, AO1… side faces the top rails, and the PWMA, AIN2, AIN1, STBY… side faces down.
Every pin now owns a short column of 4 free holes. To connect to a pin, plug into its column.
Step 2 of 6 · Motor power

Battery, VM, and ground

3
Battery switch OFF. Battery red wire → top red (+) rail. Battery black wire → top blue (–) rail.
4

5

Step 3 of 6 · Brain power

ESP32 GND and 3V3

6

7
ESP32 3V3 → VCC's column. This powers the chip's logic, not the motors.

Build 1 · wake it up

Spin motor A

const int STBY = 14;
const int AIN1 = 27;
const int AIN2 = 26;
const int PWMA = 25;

void setup() {
  pinMode(STBY, OUTPUT);
  pinMode(AIN1, OUTPUT);
  pinMode(AIN2, OUTPUT);

  digitalWrite(STBY, HIGH);   // wake the chip up

  digitalWrite(AIN1, HIGH);   // direction: one way
  digitalWrite(AIN2, LOW);
  analogWrite(PWMA, 200);     // speed: 200 out of 255
}

void loop() {
}

Plug in USB, upload, then switch the battery ON. Motor A spins. 🎉

Troubleshooting

If…Check
Nothing at allBattery switch on? STBY wire on pin 14 and in STBY's column? Shared GND: ESP32 GND, battery black, and driver GND all in the blue rail?
Still nothingVCC really connected to 3V3? VM really in the red rail? Is the driver pushed all the way into the breadboard?
Motor B spins instead of AYour motor wires are in the B columns. Move them to AO1/AO2.
It twitches or humsA motor wire is loose in its column, or the batteries are weak.
The driver gets hotBattery off now. Usually VM and VCC are swapped or something is shorted. Ask for help.
Build 2 · both motors, every direction

The motor test routine

const int STBY = 14;
const int AIN1 = 27;
const int AIN2 = 26;
const int PWMA = 25;
const int BIN1 = 13;
const int BIN2 = 18;
const int PWMB = 19;

void setup() {
  pinMode(STBY, OUTPUT);
  pinMode(AIN1, OUTPUT);
  pinMode(AIN2, OUTPUT);
  pinMode(BIN1, OUTPUT);
  pinMode(BIN2, OUTPUT);
  digitalWrite(STBY, HIGH);
  analogWrite(PWMA, 200);
  analogWrite(PWMB, 200);
}

void loop() {
  // 1. A forward, B forward
  digitalWrite(AIN1, HIGH); digitalWrite(AIN2, LOW);
  digitalWrite(BIN1, HIGH); digitalWrite(BIN2, LOW);
  delay(2000);

  // 2. both coast to a stop
  digitalWrite(AIN1, LOW);  digitalWrite(AIN2, LOW);
  digitalWrite(BIN1, LOW);  digitalWrite(BIN2, LOW);
  delay(1000);

  // 3. A reverse, B reverse
  digitalWrite(AIN1, LOW);  digitalWrite(AIN2, HIGH);
  digitalWrite(BIN1, LOW);  digitalWrite(BIN2, HIGH);
  delay(2000);

  // 4. both brake
  digitalWrite(AIN1, HIGH); digitalWrite(AIN2, HIGH);
  digitalWrite(BIN1, HIGH); digitalWrite(BIN2, HIGH);
  delay(1000);

  // 5. opposite directions: A forward, B reverse
  digitalWrite(AIN1, HIGH); digitalWrite(AIN2, LOW);
  digitalWrite(BIN1, LOW);  digitalWrite(BIN2, HIGH);
  delay(2000);
}

delay() is fine for a test routine that has nothing else to do.

Watch each step

Upload, battery ON, and watch the routine a few times. On your worksheet, record what the motors do in each step.

Coast vs. brake

During step 2 (both LOW), gently spin a wheel by hand. During step 4 (both HIGH), try again. Which one resists?

Opposite directions

In step 5, the motors turn opposite ways. On a robot with one motor on each side, what would that make the robot do?

IN1IN2Motor
HIGHLOWspins one way
LOWHIGHspins the other way
HIGHHIGHbrake: stops fast, resists turning
LOWLOWcoast: power off, spins freely to a stop
STBY LOWeverything off, no matter what

One difference from the L298N: there, both LOW also braked. On the TB6612, both LOW coasts. Step 5 is how a tank (or an Antcar) spins in place.

Build 3 · one function, any speed, any direction

setMotor()

Writing three lines for every motor change gets old fast. Let's make one function that takes a speed from −255 to 255: positive is one way, negative is the other, and 0 is stop.

const int STBY = 14;
const int AIN1 = 27;
const int AIN2 = 26;
const int PWMA = 25;
const int BIN1 = 13;
const int BIN2 = 18;
const int PWMB = 19;

// speed: -255 (full reverse) to 255 (full forward)
void setMotor(int in1, int in2, int pwm, int speed) {
  if (speed > 0) {
    digitalWrite(in1, HIGH);
    digitalWrite(in2, LOW);
  } else if (speed < 0) {
    digitalWrite(in1, LOW);
    digitalWrite(in2, HIGH);
  } else {
    digitalWrite(in1, LOW);     // 0 = coast
    digitalWrite(in2, LOW);
  }
  analogWrite(pwm, abs(speed));  // the size of the number is the speed
}

void setup() {
  pinMode(STBY, OUTPUT);
  pinMode(AIN1, OUTPUT);
  pinMode(AIN2, OUTPUT);
  pinMode(BIN1, OUTPUT);
  pinMode(BIN2, OUTPUT);
  digitalWrite(STBY, HIGH);
}

void loop() {
  setMotor(AIN1, AIN2, PWMA, 200);    // A forward, fast
  setMotor(BIN1, BIN2, PWMB, 100);    // B forward, slow
  delay(2000);

  setMotor(AIN1, AIN2, PWMA, -150);   // A reverse
  setMotor(BIN1, BIN2, PWMB, -150);   // B reverse
  delay(2000);

  setMotor(AIN1, AIN2, PWMA, 0);      // both stop
  setMotor(BIN1, BIN2, PWMB, 0);
  delay(1000);
}
Build 3 · how it works

The sign is the direction. The size is the speed.

CodeWhat it means
void setMotor(int in1, int in2, int pwm, int speed)A function with four inputs: which three pins belong to this motor, and how fast. One function works for both motors.
if (speed > 0) … else if (speed < 0)The sign picks the direction.
analogWrite(pwm, abs(speed))The size sets the speed. abs(-150) is 150.
Sound familiar? In Lesson 5, diff worked the same way: its sign said which way to turn, and its size said how hard. That's not a coincidence. Soon, the eyes' diff will flow straight into setMotor().

📝 Investigate · worksheet C

Is the TB6612 really better?

Find motor A's starting speed again: the smallest number that gets it turning from a stop. Try setMotor(AIN1, AIN2, PWMA, 60), then 50, then 40… and record where it stops working.

Compare it to your L298N starting speed from Lesson 6.

Usually the TB6612 starts the motor at a lower number. The L298N lost about 2 V before the motor got anything, so it needed a bigger PWM push. Less wasted voltage = more of each pulse reaches the motor. Your numbers may vary with batteries and motors; that's real data.

Smooth start

Instead of jumping to 200, ramp from 0 to 200 over one second using millis(). Real robots do this so they don't jerk or slip.

Kill switch

Put a wire on pin 4 with INPUT_PULLUP (Lesson 1!). When it touches GND, set STBY LOW: an emergency stop for both motors.
